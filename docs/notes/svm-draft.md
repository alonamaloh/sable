# SVM draft: what formalizing §10 forced (design-audit note)

> **Status: all eleven findings resolved 2026-08-09 — see ADR 0005 and the updated design §2.2/§2.3/§10.** This note remains as the audit trail.

*2026-08-09 design-audit artifact: `lean/Sable/SVM.lean` (core-only). The
durable differential-testing decision is ADR 0017.*

## Shape

Configurations are `run (continuation : List Stmt) (locals) | done v | trapped t` — traps are a terminal outcome distinct from normal termination. **Statements: small-step** inductive relation (`Step`), as §10 mandates; `while` unfolds, so divergence is a real behavior, not a missing derivation. **Expressions: big-step** inductive relation (`Eval`) — pure and call-free in this fragment, so evaluation cannot diverge and big-step loses nothing, while keeping every trap-*propagation* rule an explicit constructor (that is where the unmade ordering decisions hide). Values are exact `Int`s; widths live in the typed syntax (each arith node carries its `IntTy`); division is `Int.ediv`/`emod` per ADR 0004. Sanity theorems: terminality of `done`/`trapped`; `emod_inRange` (Euclidean `%` never overflows, even at signed extremes — §2.2's shared obligation row for `/` and `%` is now a theorem, not a claim).

**Scoped out** (noted in-file): function/method calls, classes/RAII, borrows as distinct values (arrays are owned values in locals — the ownership story absorbed the heap), ghost state, `match`, declarations (⊥ vs undeclared conflated), `sat`, floats, multi-frame stacks. Rule count: 55 expression + 18 statement = **73 rules**.

## Ambiguities and inconsistencies found (the real deliverable)

1. **OOM contradicts determinism (§10).** "Small-step, deterministic" and "alloc_array halts in a named OOM trap" cannot both hold in an unparameterized machine: *when* does allocation fail? Forced resolution: `Step`/`Eval` take a capacity parameter `cap`; soundness statements must quantify over it. The prose never mentions this parameter, and a per-allocation length bound (what I wrote, and what `interp.rs`'s hardcoded 50M effectively is) is not a memory account — a real one needs the heap, which needs the ownership formalization.
2. **Reading ⊥ vs pillar 1.** Pillar 1: "every syntactically valid program has a meaning." §2.3/§10: verified programs never read ⊥. But a syntactically valid, *unchecked* program that reads ⊥ has no rule — it is stuck, exactly the UB-shaped hole pillar 1 forbids. The design must either restate pillar 1 over *checked* programs, give ⊥-reads a defined trap (which would make definite-init deferrable — a §9 policy question), or add a distinct `undef` terminal outcome so the soundness theorem can name it.
3. **`wrap()`/`checked()`/`sat()` cannot be functions.** As written in §2.2, `wrap(seed * 2654435761)` applies `wrap` to an argument whose own semantics already traps on overflow. They must be operator *modifiers* (I modeled `wrapArith`/`checkedArith` as separate node kinds). Unanswered: how deep does the modifier reach — `wrap(a*b + c)` top operator only, or the whole subtree? And `wrap` on signed types (two's-complement assumed; only an unsigned example exists in the prose).
4. **Evaluation order is unstated, but trap identity depends on it.** A deterministic machine must fix which of two possible traps fires (`a[i] + 1/0`; `a[bad] = 1/0`). Chosen: left-to-right everywhere; for `a[i] = e`, index → value → bounds check, matching `interp.rs` — where the value's trap beating the OOB trap is itself an undocumented decision. Deserves a normative paragraph or ADR.
5. **Short-circuit `&&`/`||` is never stated.** The guarded-VC idiom (`i < a.len && a[i] > 0`) requires it, and `interp.rs` implements it with a comment "matching the VC semantics" — but no design text says the operators short-circuit. Normative gap.
6. **§10's "typed stack machine" has no instructions.** The config is ⟨code, frames, heap, ghost⟩ and the semantics "~40 rules", but no instruction set exists anywhere; rules can't be written against unspecified instructions. I formalized structured (AST-level) code instead. Also "~40 rules" undercounts ~2× once trap propagation is explicit (73 here, with calls/classes/ghost still missing); either the estimate assumed functional expression evaluation or stack code — say which.
7. **Two trap vocabularies.** Machine traps are structural (`overflow t`, `indexOOB i len`, …); §9/§10's "named trap" names are content-anchored *compiler* artifacts. Which is machine-observable? For `defer` the name must survive into machine syntax (modeled: `check name c` / `deferViolation name`). Whether ordinary traps carry data (index, length) is an observability question the "defined behavior" claim needs answered.
8. **Fall-off-the-end return.** `swap` (§5) has no `return`; the machine needs a rule for the empty continuation (chosen: returns `unit`). The prose never mentions unit-valued functions or a definite-*return* analysis (§2.3 covers initialization only).
9. **The `ghost` config component has no transitions.** §10 puts `ghost` in the configuration, but no construct anywhere is given ghost-state semantics (ghost assignment, `old` snapshots). Erasure is claimed sound, yet the un-erased machine it erases *from* is unspecified. Scoped out here; blocking for the erasure metatheorem.
10. **Big-step expressions die the day calls land.** Sound now only because expressions cannot diverge. With calls in expressions the design must choose: A-normalize calls into statements (consistent with "stack machine") or move expressions into the small-step relation. Prose silent; this decision shapes the whole formalization.
11. **Minor:** out-of-range literals (stuck here; typechecker duty unstated) · unary `-` on unsigned traps unless operand is 0 — is it even legal? · negative `alloc_array` length (stuck; excluded by `u64` typing?) · `bool == bool` and mixed-width comparisons unspecified (machine compares on ℤ, so it's purely a checker question) · max array length / `a.len`'s program type (`u64`?) unstated.

**Confirmations** (rules agreed with prose): Euclidean `/`+`%` semantics and the MIN / -1-as-representability equivalence (ADR 0004); `%` needing no overflow rule; bounds-checked `Seq.get` matching the total-with-junk ghost lift; loop annotations erasing cleanly (machine `while` needs nothing).

## Suggested next steps

Determinism of `Step`/`Eval` (the rule side conditions were written to be mutually exclusive — proving it is the cheapest regression test of that claim); a functional evaluator + agreement proof, giving the differential-testing oracle against `interp.rs`; then calls + frames, which forces §10's stack for real.

> **Status 2026-08-10: the first two are done** — the machine gained the `undef` outcome (total, per ADR 0005 res. 1), the evaluator and both agreement directions are proven (`lean/Sable/SVMEval.lean`; determinism/totality/progress are corollaries), and the differential harness runs in `cargo test` over `corpus/svm-diff` (ADR 0017). Calls + frames remain.
